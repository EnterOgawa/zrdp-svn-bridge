# Remote Desktop ActiveX host方式の提案

作成日時: 2026-07-30 12:31:19（Asia/Tokyo）

## 1. 結論

`ZRdpSvnBridge.exe`のRemote Desktop ActiveX hostには、Visual Studio 2022 Build ToolsのATL componentと`CAxWindow`を使用する。

RDP protocol、認証、画面転送、入力転送はWindowsにインストール済みのRemote Desktop ActiveX Controlへ委譲する。ATLはActiveX containerの定型的なCOM／OLE処理だけに使用し、製品固有のRDP設定、event処理、Bridge処理は専用classへ分離する。

## 2. 変更対象

新規作成を予定する主なファイルと責務は次のとおりである。実際の名称はCMake scaffold作成時に最終確認する。

| ファイル | 主なclass／function | 役割 |
|---|---|---|
| `src/client/rdp/rdp_import.h` | Type Library import境界 | `mstscax.dll`のCOM typeを内部へ限定する |
| `src/client/rdp/rdp_control_host.h/.cpp` | `RdpControlHost` | ATL host window、ActiveX生成、設定、接続、切断、破棄 |
| `src/client/rdp/rdp_event_sink.h/.cpp` | `RdpEventSink` | `IMsTscAxEvents`のConnection Point購読と解除 |
| `src/client/app/main_window.h/.cpp` | `MainWindow` | Win32 UI、Window／全画面切替、状態表示 |
| `src/client/app/main.cpp` | `wWinMain` | COM STA、ATL host初期化、message loop |
| `src/common/com_ptr.h` | 必要な場合のみ | ATLで不足する所有権境界の補助。raw owning pointerは持たない |

## 3. 選択理由

### ATL `CAxWindow`

- MicrosoftがActiveX control containment用として提供している。
- `CreateControlEx`でhost作成とcontrol interface取得を定型化できる。
- Visual Studio 2012以降のATLはheader-onlyで、ATL redistributableを製品へ同梱する必要がない。
- COM interfaceを`CComPtr`、BSTRを`CComBSTR`等で所有できる。
- 独自OLE containerに必要な多数のinterface実装を減らし、lifecycle、in-place activation、focus、window resizeの欠陥riskを抑えられる。

### 独自OLE containerを採用しない理由

- `IOleClientSite`、`IOleInPlaceSite`、`IOleInPlaceFrame`、`IStorage`等の実装量が大きい。
- focus、activation、window破棄、再入、COM参照countの誤りがRDP Client全体のcrashへ波及しやすい。
- 本製品の価値はSVN Bridgeであり、汎用ActiveX containerを独自実装することではない。

### MFCを採用しない理由

- 現行方針はWin32 desktop applicationであり、MFC application frameworkを追加する必要がない。
- UI全体のownershipとmessage dispatchをWin32のまま明確に保つ。

## 4. Tool dependency

- 追加component: `Microsoft.VisualStudio.Component.VC.ATL`
- 配置先: 既存のVisual Studio Build Tools 2022 installationである`C:\develop\tools\Microsoft`
- 対象: v143 x86／x64 ATL。ただし製品targetはx64だけとする。
- 製品runtime dependency: 追加しない。
- vcpkg、Conan、NuGetは使用しない。

追加後は`vswhere`と`atlbase.h`／`atlhost.h`の存在を確認し、最小`CAxWindow` buildで検証する。

## 5. Type Library境界

Windows SDK 10.0.26100.0には`mstscax.h`がないため、MSVCの`#import`で実行環境の`mstscax.dll` Type Libraryを使用する。

ローカル検証により、`/W4 /WX`では次の重複型を明示的に除外する必要がある。

```cpp
#import "mstscax.dll" \
    raw_interfaces_only, raw_native_types, no_namespace, named_guids, \
    exclude("wireHWND", "_RemotableHandle", "__MIDL_IWinTypes_0009")
```

- `#import`は`src/client/rdp/rdp_import.h`だけに置く。
- 生成される`.tlh`／`.tli`はbuild directory内の生成物とし、Gitへ登録しない。
- 利用可能な最新CLSIDから順に生成を試し、version依存処理は`RdpControlHost`内へ閉じ込める。
- Windowsの`mstscax.dll`を製品へコピーまたは同梱しない。

## 6. Security boundaryへの影響

### ActiveX／COM

- `CoInitializeEx(nullptr, COINIT_APARTMENTTHREADED)`、ActiveX生成、event購読、接続、切断、破棄はUI threadだけで行う。
- `AtlAxWinInit`はCOM STA初期化後に呼び、host window破棄後に終了処理を行う。
- Connection Point cookieはRAIIで管理し、control破棄前に必ず`Unadvise`する。
- COM callbackからC++例外を漏らさない。
- certificate／authentication warningを自動承認しない。

### Virtual Channel

- Phase 0ではActiveX接続成立確認に限定する。
- Phase 1以降、`CreateVirtualChannels("ESVNBRG")`は`Connect`前に`RdpControlHost`から必ず呼ぶ。
- BSTR binary payload処理はUI classへ置かず、専用adapterへ分離する。

### HTTP Proxy／Agent Socket

- Phase 0のhost方式による直接影響はない。
- HTTP解析、Socket I/O、待機処理をCOM UI threadへ追加しない。

## 7. Protocol compatibilityへの影響

- Phase 0ではApplication Protocolを実装しないため、wire compatibilityへの影響はない。
- `ESVNBRG`の名称は変更しない。
- ActiveX control versionの違いをApplication Protocol versionとして扱わない。

## 8. Test観点

- ATL componentを含むVS2022 toolchainでx64 Debug／Release buildが成功する。
- ActiveX host windowを生成、resize、破棄できる。
- 利用可能なRDP control versionを検出できる。
- control生成失敗時にHRESULTを保持して安全に終了する。
- event sinkの`Advise`／`Unadvise`が対になる。
- 接続前破棄、接続中close、切断後再接続でuse-after-freeがない。
- Window／全画面切替後にfocusとkeyboard／mouse inputを維持する。
- `RedirectClipboard`を接続前に有効化できる。
- ATL DLL等の追加runtime dependencyが製品EXEにないことを`dumpbin /dependents`で確認する。

## 9. Rollback

- ATL component追加自体はbuild toolだけに影響し、製品runtimeやOS RDP設定を変更しない。
- ATL hostが要件を満たさない場合は、該当sourceとCMake dependencyを削除して開発基盤時点へ戻す。
- rollback時も`mstscax.dll`、registry、Zscaler、Firewall、GPOを変更しない。
