# ZRdp SVN Bridge セキュリティ

ZRdp SVN Bridgeは、既存のRDPセッションと、利用を許可されたHTTP SVN／Tracの通信を使います。
利用環境のWindows・ネットワーク・組織のセキュリティ制限を変更しません。

## 通信先の制限

ClientのHTTP Proxyは `127.0.0.1` だけで待ち受けます。
Agentは登録されたIPv4アドレス・TCPポートと完全一致する宛先にだけ接続し、
接続先PCで新しい受信ポートを開きません。

ホスト名、DNS、CIDR、ワイルドカード、ポート範囲、HTTPSトンネルや汎用転送は扱いません。
未登録の宛先、不正な設定、互換性のないプロトコル、過大なフレームやキューは拒否します。
別ポート、OSのProxy、直接接続などへの自動フォールバックもありません。

Client／Agent間はRDPのStatic Virtual Channel `ESVNBRG` を使用します。
独自の暗号化やVPNを追加せず、Windowsが確立したRDP通信を利用します。
対応範囲の詳細は [既知の制約](known-limitations.md) をご覧ください。

## 認証と保存情報

RDP認証はMicrosoftの標準UI、SVN／Trac認証は外部クライアントとサーバーに任せます。
ZRdp独自のパスワード保存機能はありません。証明書警告や認証警告を自動承認せず、
NLA、CredSSP、証明書ストア、GPO、Firewall、Zscalerの制限を変更・回避しません。

接続履歴と接続別Agent設定は、Windowsユーザー単位のDPAPIで暗号化します。
別接続へAgent設定を推定して引き継ぐことはありません。
マイク転送は既定OFFで、音声の内容を解析・保存しません。

DPAPIは、同じWindowsユーザーとして動作するプロセスや管理者に対する完全な防御ではありません。
接続先の `agent.ini`、配置用の一時INI、バックアップは平文で、ユーザー限定のアクセス権で保護します。
保存場所は [設定](configuration.md) をご覧ください。

## Agent配置と固定入力

RDP認証後、接続ごとの登録済み設定に基づき、専用の配布ドライブと固定のAgentだけを使用します。
配置先は接続先ユーザーの `%LOCALAPPDATA%\ZRdp` です。
リンク、不正なファイル、使用中のファイル、検証・バックアップに失敗した更新は拒否します。
任意のコマンド、パス、PIDを渡す仕組み、強制終了、サービス・ログオン自動起動登録はありません。

設定変更では既存のHTTP通信を終了し、設定をバックアップ付きで更新して協調再起動します。
最新設定のAgent応答が得られるまでProxyを利用可能にしません。

固定のWin＋R・Ctrl＋V・Enterは、対象の前面・フォーカス・認証世代・クリップボードを確認して送ります。
途中で条件が変わった場合や部分受付では再送しません。
ただし直前確認後の画面切替との競合は残るため、自動起動中は入力やウィンドウ切替を控えてください。
クリップボードは復元しません。Windowsの警告は利用者が確認します。

通常起動やAgent配置では署名を必須にしません。
製品情報・同一版・ファイル安全性は検証しますが、製品情報だけで発行者や改ざん防止を証明できるわけではありません。
信頼できるソース・配布元を使用してください。

## セット更新

自動更新は、同じReleaseのClient／Agentを利用者の同意後に取得します。
両EXEの署名、timestamp、現行Clientとの発行者公開鍵一致、SHA-256、
同一版と固定の製品情報を検証し、すべてのRDP・設定画面を閉じて保存が完了した後に適用します。

署名・通信・権限検証に失敗した場合は更新を停止します。
認証token、任意URL、管理者昇格、RDPの強制切断、他プロセスの強制終了は使用しません。
部分置換失敗時は旧セットへの復元を試み、復元できない場合はstageと旧版を保全します。
電源断等で二つのファイルを同時に置換できる保証はありません。
操作と復旧方法は [セット更新](client-updates.md) をご覧ください。

## 診断と報告

診断は固定イベント名、状態、件数、転送量、エラーコードに限定します。
接続先、ドメイン、ユーザー名、認証情報、URL、Cookie、HTTP本文、ソース・差分、
Tracのticket・comment・attachment、クリップボード内容は診断ログへ記録しません。

ログやダンプを公開する前に、機密情報が含まれないことを確認してください。
脆弱性は [非公開の報告窓口](../SECURITY.md) を利用し、公開IssueやPRへ詳細を投稿しないでください。
